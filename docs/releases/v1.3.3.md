# v1.3.3 — Electron Host 独立桌宠启动修复

## 修复

修复安装独立 Electron 运行时后，命令行 `status` 显示 Ready，但 DSH Desktop 仍只显示页面内桌宠的问题。根因是 Host 的 Electron ASAR 虚拟文件系统把运行时中的 `resources/default_app.asar` 当作虚拟目录，导致物理文件校验失败。

- 在 Electron Host 中使用局部 `original-fs` 检查物理文件；普通 Node 使用 `node:fs`。
- 不更改全局 `process.noAsar`，不跳过哈希校验、链接拒绝或路径检查。
- 保留 1.3.2 的合并查询框、橙色星标收藏和收藏优先排序。

## 验证

- 设置 `DSH_TEST_ELECTRON` 为实际 DSH Electron 可执行文件后，完整测试 170/170 通过；新增回归确认可识别运行时，同时拒绝被改写的 ASAR 文件。
- 同一 Host 执行环境下，实际桌宠启动至 `BRIDGE_READY` 并正常退出，使用隔离偏好目录。未把 CLI Ready 结果当作启动成功，也未宣称完整用户会话 GUI 交互验收。

## 更新

先停用插件，执行：

```powershell
dsh plugin --profile desktop add dsh-cgss-idol-theme@1.3.3
```

使用 DSH Desktop 自带 CLI。已有有效 Electron 44.5.1 缓存无需重新安装。更新后启用插件，并完整退出、重启 DSH Desktop 与 Host。原 1.3.2 的本机临时修复可由本正式版本替代。
